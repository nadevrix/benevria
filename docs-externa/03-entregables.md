# Entregables — checklist

Todo esto se sube a la plataforma oficial del hackathon.

## 1. 🎥 Video Pitch (2–3 min)
Presenta: problema → solución → propuesta de valor → **cómo usa Arbitrum**.
No es el demo. Es el "por qué".

## 2. 📑 Pitch Deck (PDF)
La presentación usada en el pitch. Estructura sugerida (8-10 slides):
portada / problema / usuario / solución / demo screenshot / arquitectura /
por qué Arbitrum+Stylus / tracción o siguiente paso / equipo / contacto.

## 3. 🚀 Link Demo
URL de la app desplegada donde los jurados puedan probarla.
→ **Aquí entra Render**: el frontend Next.js desplegado públicamente.

## 4. 🎬 Video Demo
Video mostrando el funcionamiento y las funcionalidades principales.
Grábalo con anticipación: es el seguro contra fallos de red el día del pitch.

## 5. 💻 Link Repositorio Público
GitHub público, con código fuente **y documentación**.
El README debe incluir instrucciones de instalación y ejecución.

## 6. 📜 Smart Contracts
Por **cada** contrato desplegado:
- Dirección del contrato (`0x...`)
- Red de Arbitrum utilizada
- Enlace al explorador (Arbiscan)

> Mantener esto en una tabla en el README desde el primer despliegue, no al final.

## 7. 🏗️ Link Arquitectura
Diagrama de arquitectura (Excalidraw, Figma, Miro, **Mermaid**, u otra) mostrando
la interacción entre los componentes principales.

> Mermaid es lo más rápido: se escribe en el propio README y GitHub lo renderiza.
> Cero herramientas externas, cero tiempo perdido.
